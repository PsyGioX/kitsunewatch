1. ЧТО ЭТО И КАК РАБОТАЕТ
---------------------------------------------------------------------
Секретная ссылка — это обычный адрес сайта с кодом, который открывает
поверх страницы красивую карточку: список ссылок на соцсети проекта
или плейлист (подборка аниме и музыка).

Три равноценных формата адреса (код — например, fox-club):

    https://kitsunewatch.vercel.app/s/fox-club        <- красивый
    https://kitsunewatch.vercel.app/?s=fox-club       <- то же самое
    https://kitsunewatch.vercel.app/#s=fox-club       <- через #

Что происходит при открытии:
  - сайт грузится как обычно, после прелоадера появляется карточка;
  - код из адреса стирается (в строке остаётся просто сайт), чтобы
    ссылку не «засветили» случайным скриншотом;
  - если кода нет в списке — ничего не происходит, сайт открывается
    как обычно и НЕ подсказывает, что такая функция вообще существует;
  - в карточке есть кнопка «Скопировать ссылку» — она копирует
    адрес вида /s/код, чтобы им можно было поделиться;
  - закрыть карточку: крестик, Esc или клик по затемнённому фону.

Файлы модуля (папка /secret-links):
  secret-links.js / .min.js   логика (трогать не нужно)
  secret-links.css / .min.css оформление в стиле сайта (учитывает тему)
  data/secrets.json           ВСЕ ваши ссылки — редактируется только он
  SECRET-LINKS-GUIDE.txt      эта инструкция


---------------------------------------------------------------------
2. ЧЕСТНО О «СЕКРЕТНОСТИ»
---------------------------------------------------------------------
Это «ссылка по секрету», а не защита паролем. Сайт статический, и
файл data/secrets.json отдаётся браузеру целиком. Поэтому:

  - Любой, кто догадается открыть /secret-links/data/secrets.json,
    увидит все карточки и их содержимое. Не кладите туда ничего
    действительно приватного (пароли, личные данные, платные ссылки).
  - Если у карточки указан "code" открытым текстом, его видно в файле.
  - Если указан "codeHash" (раздел 8), сам код в файле не виден.
    Но короткий или простой код (например, "anime") подбирается
    перебором за секунды. Делайте код длинным и необычным:
    "tihii-vecher-7k2" надёжнее, чем "secret".
  - В репозитории GitHub (если он публичный) файл тоже виден всем.
  - robots.txt и заголовок X-Robots-Tag просят поисковики не
    индексировать /s/ и данные, но это просьба, а не защита.

Для чего это подходит: «закрытые» подборки для подписчиков,
анонсы, пасхалки, ссылки «для своих», реферальные площадки.
Для чего НЕ подходит: всё, что нельзя показывать посторонним.

3. БЫСТРЫЙ СТАРТ (2 МИНУТЫ)
---------------------------------------------------------------------
1) Откройте secret-links/data/secrets.json.
2) В массив "entries" добавьте блок (запятая между блоками!):

    {
      "id": "my-first",
      "type": "playlist",
      "code": "moya-podborka-4x9",
      "title": "Моя подборка",
      "description": "Три тайтла на вечер.",
      "items": [
        { "type": "anime", "title": "Мастер муси", "query": "Mushishi" }
      ]
    }

3) Сохраните, задеплойте (git push, если сайт на Vercel).
4) Откройте  https://ваш-сайт/s/moya-podborka-4x9

Правила кода ("code"):
  - только латиница a-z, цифры, дефис "-" и подчёркивание "_";
  - длина от 2 до 64 символов;
  - регистр не важен (FOX-Club = fox-club);
  - код должен быть уникальным среди всех карточек.

4. СТРУКТУРА data/secrets.json
---------------------------------------------------------------------
Файл — это JSON. Следите за запятыми и кавычками: "лишняя запятая"
в конце списка ломает весь файл (сайт тогда просто молчит).
Проверить файл можно на jsonlint.com или командой:
    node -e "JSON.parse(require('fs').readFileSync('secret-links/data/secrets.json','utf8'));console.log('OK')"

Общие поля любой карточки:

  id           (желательно) внутреннее имя, латиницей. Уходит в событие
               kw:secret-link, на экране не показывается.
  type         "social" или "playlist"  (обязательно)
  code         открытый код  ИЛИ
  codeHash     хэш кода (раздел 8). Нужно указать одно из двух.
  title        заголовок карточки
  description  короткий текст под заголовком
  enabled      false — карточка выключена, но остаётся в файле.
               По умолчанию true.
  unlockAt     когда карточка станет доступной (раздел 7)
  expiresAt    когда карточка перестанет работать (раздел 7)

Поле только у playlist:
  mood         маленькая «этикетка» под заголовком, например
               "дождь · чай · 3 серии"


---------------------------------------------------------------------
5. ТИП «social» — СОЦСЕТИ И БУДУЩИЙ КОНТЕНТ
---------------------------------------------------------------------
Показывает список ссылок-кнопок. Каждая ссылка:

  label     подпись (обязательно)
  url       адрес, ТОЛЬКО http:// или https://  (обязательно)
  icon      иконка Bootstrap Icons, например "bi-telegram",
            "bi-youtube", "bi-discord", "bi-twitter-x",
            "bi-people", "bi-broadcast", "bi-music-note-beamed".
            Список иконок: icons.getbootstrap.com
            (нет такой иконки — покажется значок ссылки)
  note      мелкая подпись под названием
  unlockAt  дата открытия ЭТОЙ ссылки. До этого момента вместо кнопки
            серая строка с замочком и надписью
            «Откроется 10 января 2027 г. в 20:00».

Так можно заранее «пообещать» будущий контент: ссылка уже лежит в
списке, но станет нажимаемой только в назначенное время. Менять
файл и делать деплой в этот момент не нужно.

Важно: до открытия адрес (url) всё равно виден в файле JSON тому,
кто его откроет вручную (см. раздел 2). Если адрес нужно скрыть до
даты — добавьте ссылку в файл только в день публикации.


---------------------------------------------------------------------
6. ТИП «playlist» — ПЛЕЙЛИСТЫ
---------------------------------------------------------------------
Показывает нумерованный список. Элемент ("items"):

  type    "anime" | "music" | "link"   (по умолчанию "anime")
  title   название (обязательно)
  note    мелкая подпись
  query   (только anime) что искать на сайте. Если не указан —
          ищется по title.
  url     (music и link) внешний адрес http/https

Поведение кнопок:
  anime  -> кнопка «Смотреть» открывает  /?search=<query>  и запускает
            обычный поиск KitsuneWatch по этому запросу.
  music  -> кнопка «Слушать» открывает ссылку в новой вкладке
            (YouTube, Spotify, Яндекс Музыка, SoundCloud — что угодно).
  link   -> кнопка «Открыть», тоже в новой вкладке.

Совет по query: проверьте, что поиск реально находит тайтл.
Откройте  /?search=Mushishi  и посмотрите. Иногда лучше работает
русское название, иногда оригинальное — подберите вручную и
запишите в query. В title можно писать красивое название для людей,
а в query — то, что находит поиск.

Музыка — это только ссылка во внешний сервис. Сайт ничего не
воспроизводит сам (так устроена политика безопасности сайта —
встроенные чужие плееры запрещены).


---------------------------------------------------------------------
7. ОТЛОЖЕННЫЙ КОНТЕНТ: unlockAt / expiresAt / enabled
---------------------------------------------------------------------
Формат дат — ISO 8601 с часовым поясом:

    "2027-01-10T20:00:00+03:00"     10 января 2027, 20:00 по Москве
    "2026-12-31T23:59:00Z"          Z = время по Гринвичу (UTC)

ВСЕГДА указывайте пояс (+03:00 или Z), иначе дата будет понята по
часам устройства посетителя.

  unlockAt на карточке   до даты открывается заглушка:
                         «Эта страница откроется 10 января 2027 г.
                         в 20:00. Загляните позже.» Название и описание
                         при этом видны — можно использовать как тизер.
  expiresAt на карточке  после даты: «Эта ссылка больше не активна.»
  unlockAt на ссылке     см. раздел 5.
  enabled: false         карточка полностью «молчит», как будто её нет.

Время проверяется по часам устройства посетителя. Если у человека
сбиты часы, он может увидеть контент раньше или позже. Для
критичных сроков это не подходит.

8. СКРЫТЫЕ КОДЫ (ХЭШИ)
---------------------------------------------------------------------
Чтобы сам код не лежал в файле открытым текстом, храните его хэш.
Формула:  SHA-256 от строки  "kw:" + код_в_нижнем_регистре
Результат — 64 символа из 0-9 и a-f. Подставьте в "codeHash" ВМЕСТО
"code".

Способ A — Node.js (в терминале):
    node -e "console.log(require('crypto').createHash('sha256').update('kw:'+process.argv[1].toLowerCase().trim()).digest('hex'))" rainy-window-7

Способ B — Python:
    python3 -c "import hashlib,sys;print(hashlib.sha256(('kw:'+sys.argv[1].lower().strip()).encode()).hexdigest())" rainy-window-7

Способ C — консоль браузера (F12 -> Console, на странице сайта):
    crypto.subtle.digest('SHA-256', new TextEncoder().encode('kw:' + 'rainy-window-7')).then(b => console.log([...new Uint8Array(b)].map(x => x.toString(16).padStart(2,'0')).join('')))
  (работает на https:// и localhost)

Пример результата для rainy-window-7:
    928cdbc45e343ab626b268d8ccaa672ac9f918ecbf753dabb83cb9a1df4870c8

Запись в файле:
    { "id": "rainy-window", "type": "playlist",
      "codeHash": "928cdbc45e343ab626b268d8ccaa672ac9f918ecbf753dabb83cb9a1df4870c8",
      "title": "Окно с дождём", "items": [ ... ] }

Хэши не работают, если страница открыта по http:// (не localhost):
браузер отключает криптографию на небезопасных адресах. На
Vercel (https) всё в порядке.

  "title": "Ночь премьер",

  "description": "Подборка к первому эфиру сезона.",

«ссылка больше не активна».

--- 9.4 Отдельная ссылка под каждую площадку ----------------------
Чтобы понимать, откуда пришли люди (ручной подсчёт), заведите
одну карточку под каждую площадку с РАЗНЫМИ кодами, но одинаковым
содержимым: "tg-5k2", "vk-9m1", "yt-3p7". Автоматического счётчика
в модуле нет. При открытии карточки срабатывает событие
document 'kw:secret-link' (detail: { id, type }), его можно
подключить к аналитике или системе достижений позже.

--- 9.5 Временно выключить ----------------------------------------
Добавьте в карточку  "enabled": false  — и она замолчит.
Удалять не нужно, включите обратно, когда понадобится.

10. ПРОВЕРКА ЛОКАЛЬНО И ПУБЛИКАЦИЯ
---------------------------------------------------------------------
Локальная проверка (в корне проекта):
    python3 -m http.server 8000
    затем откройте   http://localhost:8000/?s=fox-club

ВАЖНО: короткий адрес /s/код работает только на Vercel (его делает
правило rewrites в vercel.json). Локально используйте ?s=код. Сам код
сайт читает и из пути /s/код, и из ?s=код, и из #s=код.

Публикация:
  - Правка data/secrets.json НЕ требует сборки (npm run build
    не нужен). Просто закоммитьте и запушьте.
  - Файл отдаётся с Cache-Control: no-cache, так что новые
    карточки появляются быстро. Из-за service worker (sw.js)
    у вернувшегося посетителя первый заход может показать
    старую версию, со второго — уже новую.
  - Если вы правили сам secret-links.js или .css, выполните
    npm run build: он пересоберёт .min-файлы и обновит ?v=... в
    index.html.

11. РЕШЕНИЕ ПРОБЛЕМ
---------------------------------------------------------------------
Карточка не появляется на сайте, а в адресной строке остаётся /s/код:
  - Это нормально для Vercel: адрес /s/код переписывается сервером на
    главную, а код читается из пути. Если карточки нет, проверьте, что
    в vercel.json есть блок  "rewrites": [{ "source": "/s/:code",
    "destination": "/?s=:code" }]  и что после деплоя файлы
    secret-links.min.js / .min.css отдаются (вкладка Network).
  - Сообщения в консоли про «Content Security Policy ... 'none'
    (report-only)» и про data:text/plain с шейдерами приходят от
    расширений браузера и к сайту отношения не имеют.

Карточка не появляется:
  - Проверьте код: латиница, цифры, - и _, без пробелов.
  - Проверьте "enabled" (не false) и что указан code или codeHash.
  - Проверьте JSON на ошибки (раздел 4). Откройте консоль (F12):
    ошибка в secrets.json видна во вкладке Network (файл
    secrets.json отдаётся, но не читается).
  - Для codeHash: открыта ли страница по https:// или localhost?
  - Хэш считался от строки в нижнем регистре и с префиксом "kw:"?
  - Проверьте адрес /secret-links/data/secrets.json в браузере:
    файл открывается и содержит последние правки?
  - Попробуйте открыть в режиме инкогнито (мешает старый кэш).

Кнопка «Смотреть» ведёт на пустой поиск:
  - Проверьте query: откройте /?search=ваш_запрос вручную.

Ссылка не нажимается, а показан замочек:
  - Не наступило unlockAt (время сверяется по часам устройства).

Сломался JSON:
  - Чаще всего: лишняя запятая после последнего элемента, пропущена
    запятая между блоками, обычные кавычки заменились «ёлочками».
